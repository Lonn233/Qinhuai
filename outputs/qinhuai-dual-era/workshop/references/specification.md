## 1. 执行原则

先检查现有项目结构、Three.js
版本、渲染入口、坐标规范、相机与交互系统，再按模块接入。不得重建项目或破坏现有秦淮灯会地图、相机、UI、灯饰图鉴和其他玩法。

实现优先级：

1.  **结构正确**：竹骨架圈条、纵向竹条、腰箍、绑扎点及花瓣固定位置应有清晰关系。
2.  **工艺可信**：原材料、半成品、工具和成品来自同一套尺寸与定位配置。
3.  **外观还原**：花瓣粉紫色、柔和的尖端色差、纵向压纹、底部绿叶托、顶部花头和红色/深红色内衬或承托区域，均以参考图为准。
4.  **可拆装**：所有关键部件能单独选择、隐藏、拆开、复位，并能按工序装配。
5.  **性能可控**：重复几何和材质尽量共享；不要用大量高面数线条模拟纸纹。

不要把截图直接贴在平面上冒充 3D 模型。截图只作为建模和工艺参考。

## 3. 成品外观还原要求

### 3.1 花瓣

-   花瓣主体为**柔和的粉紫/藕紫色**，不能变成粉白色，也不能过度鲜艳偏荧光紫。
-   花瓣尖端可以比周围略深，但只允许柔和的紫粉色加深，禁止黑尖、黑斑或突兀的深色三角形。
-   表面有细密、连续的纵向压纹/脉络，纹理应顺着花瓣长轴走向；不能用随机噪点替代。
-   单片花瓣不是平面贴片：需要有轻微拱起、凹面、边缘卷曲和压模形成的纵向起伏。
-   花瓣各层采用交错排列，尺寸和倾角随层次变化；避免整齐排列成机械齿轮或重复球壳。
-   花瓣背面可稍暗，但不能出现不符合纸料的厚重塑料质感。

### 3.2 竹骨架与绑扎

**三圈骨架的结构补充（必须落实到模型）：**

- 荷花灯的基础骨架由三种圆形圈条共同构成：**大圈、口圈、腰箍**。三者不是同一个尺寸的重复圆环，而是分别承担主体外轮廓、开口边缘和腰身收束的作用。
- 大圈与小圈共同限定灯体的纵向轮廓。通过圈径差、圈条高度和纵向竹条的弧度，形成类似人体腰身的柔和椭圆/收腰形态；不能把主体做成上下等宽的圆柱，也不能简单做成规则球体。
- `口圈` 指灯体开口处的圈条，`腰箍` 位于主体腰身区域；`大圈` 构成主体较大的环形骨架。请将三个圈分别建模并设置独立 ID、尺寸参数和装配关系。
- 由于参考截图没有提供精确尺寸，圈径比例应由统一配置控制，先依据四视图拟合，再允许在调试面板中微调。纵向竹条应沿三圈的对应连接点自然弯曲，确保外轮廓连续。
- 骨架调试视图必须能分别显示/隐藏大圈、口圈、腰箍和纵向竹条，以便检查“收腰”效果以及每个节点是否真正连接。

建议配置字段：

```js
frame: {
  bigRingRadius: 1.00,
  mouthRingRadius: 0.62,
  waistHoopRadius: 0.78,
  bigRingHeight: 0.18,
  mouthRingHeight: 1.00,
  waistHoopHeight: 0.56,
  verticalRibCount: 12
}
```

以上为比例调试的占位初值，不是传统工艺的固定尺寸；需按四视图与成品比例校准。


-   竹条为浅黄绿至暖浅褐色的细长材料，具有微小自然弯曲；不要做成粗木棍或金属管。
-   骨架至少包括：大圈、腰箍/中间圈、纵向竹条、必要的辅助支撑条和顶部连接区域。
-   纵向竹条与圈条相交的位置需要有真实的绑扎节点。绑扎可用白色或浅米色细绳/纸带表现，形态应紧贴竹条，不得悬空。
-   每个绑扎点应单独建模并绑定到对应竹条交点；外观近景可看到绕线圈数和短尾，但不需要无意义地增加大量面数。
-   大圈、腰箍和其他圈条不能只靠几何交叉"看起来接上"，必须在数据层记录连接关系。

### 3.3 成品其他部件

-   保留底部绿色叶托/萼片，按成品参考图确定形状、数量和朝向。
-   顶部花头是独立子组件，包括花瓣、绿色萼片和弯曲花梗；其方位应能从成品外观中对应出来。
-   成品内侧若有深红色承托/衬底结构，应单独作为内衬或承托部件建模，不要错误地把它涂到粉紫花瓣表面。
-   默认成品为未点亮状态；不使用强自发光材质。点灯效果作为后续独立状态。

## 5. 基于截图的制作工序

### 工序 A：准备竹条与圈条

**物料：** 直竹条、可弯曲竹条/圈条、裁切后的竹条段、工作台。

**操作与模型表现：**

1.  选择竹条原料，根据目标部件长度生成对应竹条段。
2.  将大圈和腰箍弯成预定形状，显示圈条的圆弧轮廓。
3.  纵向竹条沿灯体长轴分布，与圈条在多个高度相交。
4.  使用定位点约束圈条高度、纵向竹条间距与整体轮廓。
5.  完成后生成可独立展示的"竹骨架白模"。

### 工序 B：圈条与纵向竹条绑扎

**物料：** 竹骨架、浅色绑扎线/纸带。

**操作与模型表现：**

1.  选中竹条交点，显示目标绑扎位置。
2.  玩家执行绑扎后，在交点生成贴合竹条的细绳或纸带。
3.  绑扎几何需沿竹条交点绕行，局部略有叠压；禁止使用一个白色球体代表整个节点。
4.  绑扎完成后，连接关系写入数据，骨架的节点数量与已完成工序进度保持一致。
5.  支持单独隐藏绑扎物，检查竹条本身是否正确相交。

### 工序 C：准备纸料与染色

**物料：** 未染色纸片、粉紫染料/染色工具、晾干架或放置区。

**操作与模型表现：**

1.  未染色纸料先以浅纸白/浅粉白显示。
2.  染色步骤参考截图中的粉紫色渐变纸料：染色后应以粉紫色为主，局部有柔和的深浅过渡。
3.  不要把"尖端加深"处理成黑色边缘；颜色变化必须连续、柔和。
4.  每片纸料都有唯一 ID，染色前后 ID 不变，只改变材质状态或顶点颜色。
5.  染色完成后进入晾干状态，未干纸料可略微暗一些，但不应表现为湿亮塑料。

### 工序 D：压模与花瓣成形

**物料：** 压模工具、染色纸料、已压制花瓣。

**操作与模型表现：**

1.  压模工具单独建模，外形以
    `08_花瓣_压模工具.png`、`09_花瓣_压模过程.png`
    为依据；如果截图无法确认完整工具形状，采用简化工具原型并标注。
2.  玩家将染色纸料放到模具定位区，执行压制操作。
3.  压制后，纸片变成尖椭圆/水滴形花瓣，产生中部拱起、边缘弯曲与纵向细纹。
4.  花瓣纹理方向必须与长轴一致。压模前后几何或形态参数发生变化，而不是只更换一张图片。
5.  允许用参数化网格实现压纹，不需要模拟真实物理压机或高成本软体仿真。

### 工序 E：花瓣逐层安装

**物料：** 已成形花瓣、骨架、固定用绑扎/胶黏点。

1.  每片花瓣对应成品模型中的一个确定安装点。
2.  安装时按层序从内到外或从底层向外层逐步完成，层间交错。
3.  花瓣基部应与骨架/承托位置连接；不能只把花瓣悬浮在灯体表面。
4.  完成后可以拆除单层查看内部结构。
5.  同一片花瓣从纸料、染色、压模到装配的 `partId` 必须保持一致。

### 工序 F：安装叶托、顶部花头和吊挂结构

1.  安装底部绿色叶托，确保叶片贴合主体底部并朝向合理。
2.  顶部花头作为可拆卸子组件安装，花梗应与支撑结构的连接点吻合。
3.  安装吊挂/顶部支撑部件和对应绑扎节点。
4.  检查最终外观轮廓、部件数量、连接点和穿模情况。
5.  切换到完整成品展示模式，并支持重新拆解。

## 7. 补充工艺知识与展示表达

### 7.1 三圈骨架的教学说明

在工序说明中，应明确告诉玩家：大圈、口圈和腰箍共同组成荷花灯的基本框架。大圈与较小的口圈、腰箍通过纵向竹条连接，形成上口收束、腰身柔和变化的立体轮廓。若所有圈条尺寸相同，主体容易变成直筒形，失去荷花灯应有的优美腰身。

### 7.2 染色与干燥知识卡

在染色/阴干步骤提供可跳过的知识卡：

- 浸泡时间通常约 2–3 分钟，但需根据纸张和目标颜色深度调整。
- 染色纸料需要通风阴干，避免直射阳光导致褪色。
- 黄梅雨季应特别注意湿度和发霉风险；秋冬空气较干燥时通常更利于干燥。
- 纸料必须干透后再压模，以免纸张变形或筋络不清晰。

这些是工艺知识提示，不要把季节描述硬编码成所有地区都适用的绝对规则。

### 7.3 压模工具的两种表现

- **手工压模模式：** 展示简单模具与逐片压制，突出传统手工制作的细致和耗时。
- **机械压模模式：** 以抽象、可配置的设备模型表现手摇绕线机构与气泵辅助的批量压模过程。没有足够参考图时，不要声称设备模型精准复刻了真实机器。
- 两种模式的输出必须使用同一套花瓣/叶片几何模板，保证压出的半成品最终能够安装到同一盏荷花灯上。

### 7.4 点灯展示

成品检查完成后，提供“点亮花灯”展示阶段。纸质花瓣应产生柔和透光和轻微的暖色散射，光源不应直接把整个模型照成纯白。蜡烛模式可用于工艺展示，LED 模式适合默认交互和游戏场景。最终镜头应突出纸张的轻薄、筋络和层叠结构，表现传统花灯“轻盈、澄澈”的视觉感受。

## 8. 几何与材质建议

### 花瓣网格

-   用自定义 `BufferGeometry`
    或参数化网格生成薄片；通过横向截面弧度和纵向曲线塑造自然凹凸。
-   纵向压纹优先通过顶点位移、法线贴图或程序化细纹表现；近景可增加少量浅浮雕，不要逐条堆出大量细管。
-   花瓣边缘可以轻微卷曲，尖端形态自然，不要所有花瓣复制成完全相同的刚性椭圆。
-   采用统一的花瓣参数配置控制长度、宽度、曲率、压纹强度、颜色和尖端过渡。

### 竹条与绑扎

-   竹条使用曲线生成细管网格；直条、弯条和圈条应有不同模板。
-   绑扎用细曲线或窄带绕过交点生成，跟随竹条表面；节点半径和绕线圈数集中配置。
-   对重复部件共享几何和材质；如果使用
    `InstancedMesh`，仍需保留实例索引到 `partId`
    的映射，保证可选中与可拆装。

## 10. 自检与验收

-   [ ]
    成品轮廓与四视图相符，花瓣层次、顶部花头、叶托、内衬和吊挂结构齐全。
-   [ ]
    竹骨架有大圈、腰箍、纵向竹条与真实的连接节点；隐藏花瓣后结构清晰可见。
-   [ ] 每个绑扎点贴合竹条交点，有独立 ID，可单独显示/隐藏。
-   [ ] 染色纸料、压模工具、成形花瓣与成品花瓣之间存在可追踪的状态关系。
-   [ ] 花瓣有柔和粉紫色和连续纵向压纹，尖端仅略深，不发黑。
-   [ ]
    半成品和最终成品使用相同的尺寸参数与装配定位点，不会出现尺寸对不上。
-   [ ] 花瓣可以逐层安装、拆除和复位；工序进度与真实装配状态一致。
-   [ ] 模型在现有场景加载后不影响其他资产、相机、控制器和 UI。
-   [ ] 重复进入/退出工序不会持续增加事件监听器、Draw Calls
    或未释放资源。
-   [ ]
    提供实际运行验证结果、修改文件清单，以及未能从参考图确认而采用简化方案的说明。

## 11. 建议开发顺序

1.  先按四视图制作结构白模：大圈、腰箍、纵向竹条、花瓣层、叶托和顶部花头。
2.  隐藏花瓣，检查骨架圈条和绑扎节点。
3.  实现拆装层级和统一 ID。
4.  加入染色、压模和花瓣成形物料，让半成品可追踪地转化为成品部件。
5.  实现完整工序状态机。
6.  最后打磨纸质纹理、竹材细节、光照和展示镜头。
7.  完成四视图对比、装配检查、性能检查与现有场景回归测试。

**不要先追求炫目的灯光和特效。结构、部件关系、工序闭环和颜色准确性通过验收后，再做最终视觉打磨。**
