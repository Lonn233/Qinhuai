# 上元秦淮 · 灯谜游园

在现有 Three.js 双时期秦淮场景上新增可玩的灯谜入口。保留原有建筑、河流、天空、水面、相机和现代 / 明初切换，不另建脱离原项目的场景。

## 直接游玩

项目根目录运行：

```powershell
npm run start:game
```

打开 **http://127.0.0.1:4180/lantern-festival.html**。需要本机有 Node.js，服务只监听本机。停止时按 Ctrl+C；如果服务已经运行，直接使用上述地址。端口占用时可用 `$env:PORT='4181'; npm run start:game`，并相应更改浏览器地址。

**不要双击 HTML 用 file:// 打开**，GLB 通过本地 HTTP 加载。交付已包含构建产物和模型，无须为了游玩重新优化模型或运行原来的 npm run build。

## 放置与玩法

河前广场设置五座错落的木石展台：最大的**鳖山灯**独立置于西侧，瑞狮灯和仙鹤纹灯各自保留更宽的前后通行空间，金鱼灯临近河栏，**荷花灯**移至前方水岸的小型展区。铭牌侧置，避免挡住灯体；周边只加一串暖色小灯，并移除游玩区内干扰行走的旧树木、花池和装饰人物。其他街区保留原貌。这些场景调整仅在新游戏入口生效。

使用原有两款荷花灯：hehua-main.glb 用于展台及河面，hehua_1.glb 继续作为水上荷灯。五道谜题对应五个图鉴条目，没有制作、货币或战斗系统。

1. 点击“步入灯市”，靠近灯体或谜签并将视线对准。
2. 出现提示后按 E 打开谜题；输入答案，按 Enter 或点击“揭晓”。
3. 答错可重试、可查看提示；答对后解锁对应花灯图鉴。
4. 点击“继续游园”返回场景；已解开的谜题可重复赏灯，不重复解锁。

| 操作 | 功能 |
|---|---|
| W / A / S / D，方向键 | 行走 |
| 鼠标 | 环顾；不支持鼠标锁定时按住画面拖动 |
| Shift | 加速 |
| E | 近距离对准展台后猜谜 |
| B | 花灯图鉴 |
| Esc | 释放鼠标，或关闭当前面板 |
| 现代 / 明初 | 切换原场景时期，保留谜题进度 |
| 看日景 / 赏夜灯 | 昼夜切换 |
| 全景 / 回到灯市 | 轨道相机总览 / 返回安全出生点 |

触屏提供方向按钮、拖动环顾和可点击交互提示；建议桌面 Chrome / Edge 配合键鼠。打开面板时停止移动和视角控制，输入答案不会触发 WASD。

## 存档与边界

- 存档键 qinhuai.lantern-riddles.v1，保存在当前浏览器、当前地址的 localStorage，不是云端跨设备存档。
- 刷新可恢复；清除站点数据、切换浏览器或端口会使用不同存档。
- 存储被阻止时仍能游玩，图鉴会标明只保存在本次会话。
- 游玩范围限定在河前灯市；展台和边界使用简化碰撞、固定地面与视线高度，不是整个街区的物理漫游系统。
- 模型加载失败会显示重试入口；图鉴预览复用同一个 WebGL 渲染器，不创建额外渲染上下文。

## 开发入口

```powershell
npm run build:game        # 仅构建新的轻量游戏页面
npm run test:game         # 数据、答案、状态、存储与碰撞单元测试
npm test                 # 原项目 21 项回归测试
npm run test:game:browser # 本地服务运行后，执行浏览器端到端测试
```

- game/page.html / game/festival.css：覆盖式游园界面、响应式样式。
- game/entry.js：复用 model-source.js，注册游戏控制器。
- game/festival.js：布置、模型加载、移动、射线交互、答题面板、图鉴、缩略图。
- game/data.mjs：集中配置 LANTERNS、RIDDLES、LOCATIONS、边界与出生点。
- game/state.mjs：答案规范化、去重解锁、存档、简化碰撞。
- game/assets/manifest.json：模型来源、SHA256、纹理校验、减面信息。
- lantern-festival.html / game/festival.bundle.js：可运行产物。

新增谜题时，用唯一 locationId / riddleId / unlockLanternId 绑定点位、谜题和花灯，并同步调整展台间隔与可玩边界。答案支持多个同义写法、简繁体备选以及全角 / 半角归一化。文化文字为谨慎的视觉介绍，不将意境场景作为特定年代的考据复原。

浏览器测试使用 Playwright 和 Chrome：可通过 PLAYWRIGHT_PATH 指定模块位置、CHROME_PATH 指定浏览器可执行文件、GAME_URL 指定服务地址。脚本默认使用本机 Codex 配套的 Playwright 和 Chrome。测试创建独立浏览器上下文，不清除日常浏览器存档；结果、截图在 game/tests/。

## 模型处理

新游戏使用八个轻量 GLB 衍生文件，总计约 **91.6 MB**。仅进行几何减面并保留原嵌入纹理；用户提供的 GLB 和原来的离线 index.html 未被覆盖。五种花灯与桥、亭均使用真实模型，不是图片或几何占位。

npm run prepare:game-assets 可根据 game/prepare-assets.cjs 中配置的本机原始路径重新生成衍生模型；它依赖原项目 tools/asset-deps 内的模型处理工具。日常启动不需要执行。

## 已完成验证

- 原项目回归测试 21 项；游戏单元测试 7 项。
- 浏览器实际验证五套“靠近 → 射线命中 → E → 答题 → 图鉴 → 返回”流程，空答案、错答案、提示、重复解锁、输入不触发行走、碰撞边界、双时期、昼夜、全景返回及刷新存档。
- 1440 × 900 桌面与 390 × 844 窄屏界面检查；触屏方向按钮实际移动验证。
- 模拟单个模型加载失败后重试成功、浏览器禁用存储后继续游玩；场景保留两款共 12 盏水上荷灯。异常验证脚本：node game/tests/browser-resilience.cjs。
- 八个衍生 GLB 通过 glTF Validator，0 errors；每个文件有一项切线需由加载器生成的 warning，浏览器正常加载。

这是可游玩的原型。模型纹理较多，首载仍需一定时间；帧率取决于显卡，不承诺所有手机都流畅。
