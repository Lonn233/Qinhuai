# 花灯配色文件存储

试灯室沿用 Node.js 预览服务，新增同源 JSON API，无数据库、无额外依赖。仅监听本机 127.0.0.1，不是公网多人服务。

## 启动

在项目根目录执行 `npm run start:game`，打开 `http://127.0.0.1:4180/lion-light-study.html`。
修改后端代码后需要重启该服务，不能仅刷新浏览器。端口由 `PORT` 设置；可用 `LANTERN_DATA_DIR` 设置数据目录（建议绝对路径）。

## 保存位置

- `.local-data/lantern-presets.json`：当前所有花灯的自定义方案。
- `.local-data/lantern-presets.json.bak`：上一次成功版本，每次更改前自动保留。
- 主文件损坏而备份可用时，自动恢复上一版，损坏原件保留为 `.corrupt-时间戳`。
- 主文件和备份均不可读时拒绝写入，不用空数据覆盖。备份只保留上一版，无法承诺恢复损坏前最后一次更改。
- 数据目录被静态服务禁止访问并被 Git 忽略。移动项目时需要单独保留此目录；不要把它当作可删除的构建缓存。
- 磁盘文件不依赖浏览器站点数据；重启服务、换浏览器或改变本机端口后，只要服务使用同一数据目录，仍能读取。

每次写入先写临时文件、同步到磁盘，再原子替换主文件；单服务进程串行处理修改，保存成功提示只在后端确认写入后出现。不要同时运行多个进程写同一个数据目录。

## 旧方案迁移

页面打开后尝试迁移当前浏览器、当前源下的 `qinhuai.lantern-light-studies.v1` 数据，只追加未存在的方案，不覆盖后端已存方案。保留旧键，不主动清空浏览器数据。相同 ID 不重复导入，已在后端删除的 ID 不会被旧缓存反复恢复。

若旧方案来自另一个浏览器、浏览器配置文件或 `localhost`/`127.0.0.1`/端口组合，需要在原浏览器和原地址打开新版页面才能迁移。已被清除且没有备份的浏览器数据无法由新后端找回。

新版浏览器缓存只用于断线预览，不作为持久保存成功的依据，也不会自动反向覆盖后端。连接失败时禁用保存/删除，仍能调光；点击「同步 / 重试」重新连接。保存方案按花灯分组展示，不会自动应用到正式灯会。

## 接口与验证

- `GET /api/lantern-presets`：读取所有方案。
- `POST /api/lantern-presets`：新增方案（id、lanternId、base、name、power、color）。同 ID 同内容重试安全，不允许覆盖不同内容。
- `POST /api/lantern-presets/import`：追加迁移 `{ "items": [...] }`。
- `DELETE /api/lantern-presets/:id`：删除指定方案。

JSON 请求体上限 256 KiB，最多 500 个有效方案。限制本机 Host、同源 Origin 和 JSON 写入请求，校验花灯、基础灯效、名称、颜色、亮度等字段。

运行 `node --test game/tests/preset-store.test.mjs` 验证文件持久化、并发写入、迁移去重、删除后不复活、损坏恢复、写入失败和接口边界。
## 尺寸字段（2026-10-19）

新保存方案包含可选数值字段 `sizeMeters`，单位为米，含义由花灯决定（鳖山/荷花为直径，瑞狮/金鱼为长度，仙鹤纹为高度）。服务端、前端使用 `game/lion-study/dimensions.cjs` 的同一尺寸范围校验。

保留 version 1 兼容性：旧记录没有 `sizeMeters` 时不修改原文件，应用时使用该灯的新初始尺寸；新记录的尺寸必须在允许范围内。另存为创建新 ID，不覆盖原方案。文件仍为 `.local-data/lantern-presets.json`，含上一版备份机制。

尺寸单元验证：`npm run test:light-size`。五个真实 GLB 的尺寸、输入、另存、旧数据兼容及移动端验证：`npm run test:light-size:browser`（独立临时目录，不操作用户方案）。
