# 贡名灯、鳖山灯三级性能优化

完成日期：2026-10-21。与狮子灯同样采用屏幕投影大小驱动的近、中、远三级模型，近景优先保留高质量。

| 模型 | 近景三角面 | 中景三角面 | 远景三角面 | 原主场景单档三角面 |
| --- | ---: | ---: | ---: | ---: |
| 贡名灯 | 180,216 | 29,995 | 8,000 | 61,282 |
| 鳖山灯 | 110,000 | 26,000 | 8,000 | 26,000 |

贡名灯近景从用户原始 2,563,524 面模型生成，沿用离线分区简化以限制内存占用，输出独立 gongming-high.glb，原 gongming-low.glb 不覆盖。鳖山灯近景复用 game/assets/mountain.glb。两种高精度模型的三张内嵌贴图均逐张验证与原始 GLB 的字节哈希一致。中远景仅增加几何数据，复用同一套材质、彩绘和法线贴图。

切换阈值与狮子相同：模型宽度相对视口高度小于约 10% 使用中景，小于约 3.5% 使用远景；12% 滞回，每 150ms 检查，支持透视/正交相机、zoom、世界变换。远景只用于小屏幕占比，放大后会有明显简化痕迹。

两种大型灯各只有一个实例，直接切换已有网格的几何，不额外复制场景对象。模型位置、尺寸、旋转、材质、光色和可见性包装保持原有逻辑；外溢使用固定高精度边界，不随 LOD 改变。各级几何联合边界用于保守裁剪。鳖山灯仍支持原尺寸与旋转调节。加载中远景失败时回退高精度模型。未更改存储键、预设内容、浏览器或后端存档。

主场景每次打开仍默认：水面节能、运行画质低性能。

## 验证与限制

- 13 项单元/集成测试通过，包括两种灯的真实几何、实例变换、材质共享、稳定外溢源、剔除兼容、鳖山尺寸旋转、失败回退、资源释放及狮子 LOD 回归。
- 原花灯布置集成测试通过，主场景构建通过；新增 GLB 和二进制几何资源 HTTP 200。
- 两种灯分别在隔离 Chrome 硬件默认渲染路径中实测 0→1→2→0 切换，均无着色器错误、上下文丢失或外溢偏移。贡名灯每档 1 次模型 draw call，鳖山灯每档 2 次（含原地面光晕）。
- 对比图：work/gongming-lod-comparison.png、work/mountain-lod-comparison.png；逐档数据：work/gongming-lod-browser-report.json、work/mountain-lod-browser-report.json。
- 初次同时加载的软件渲染 QA 出现着色器错误/上下文异常，已改为逐模型硬件路径检查并通过；没有据此宣称软件渲染普遍兼容。
- 未测整张地图 FPS。本次近景质量高于此前低模，下载与近景 GPU 成本会增加；三级几何保持驻留，优化的是中远景提交量，不代表同比降低显存或整图加载时间。

## 重建

1. node --expose-gc --max-old-space-size=768 tools/prepare-gongming-lantern.cjs --high
2. E:/blender/blender.exe --background --factory-startup --python-exit-code 1 --python tools/blender_large_lantern_lods.py
3. node tools/prepare-large-lantern-lods.cjs
4. node --test tools/test-large-lantern-lods.mjs tools/test-gongming-lantern.mjs tools/test-lion-lod.mjs tools/test-lantern-controls.mjs
5. node tools/test-large-lantern-lods-browser.cjs gongming
6. node tools/test-large-lantern-lods-browser.cjs mountain
7. npm run build:import
