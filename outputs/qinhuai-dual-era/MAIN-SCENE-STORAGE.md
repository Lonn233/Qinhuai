# 主地图设置：将原 Chrome 的参数保存到本机文件

## 首次保护已经调好的设置

1. 保留调好参数的 Chrome 主地图标签页，不要先清理网站数据或重置参数。
2. 在**同一个 Chrome 用户资料**中新开标签页，打开 `http://127.0.0.1:4180/chrome-settings-backup.html`。
   - 如果原地图用的是 `localhost` 或其他端口，备份页必须使用原地图完全相同的主机名和端口。不同来源的浏览器存储不互通。
   - 不要用 Codex 内置浏览器替代原 Chrome；它们的存储彼此独立。
3. 等待“已写入文件”。“未发现设置”表示没有读到原浏览器的数据，不代表备份成功。
4. 如果出现版本冲突，系统已保留浏览器原样快照，不会静默覆盖参数。确认当前 Chrome 才是要保留的版本后，点击“保留两份，并采用本浏览器设置”。

备份页不加载三维场景、不向原浏览器设置写入默认值。保留该页打开，可以继续接收旧版地图标签页写入 localStorage 的调整。只在三维内存中、原功能从未写入 localStorage 的临时预览不在备份范围。

## 后续使用

主地图左侧菜单新增“本机文件存档”，自动保存已有持久化参数，提供“立即保存”和“导出备份”。页面启动时先保护现有浏览器值，再恢复缺失设置，然后加载场景。浏览器和文件两份设置有冲突时要求确认，不用默认值覆盖旧收藏。

涵盖地图光效、逐建筑外溢及自定义颜色、建筑当前参数与收藏、手动外溢、柔光、红灯笼、龙墙分区光效与另存方案、主地图逐建筑灯效与另存方案、花灯旧收藏及文件缓存、菜单收起状态。原有花灯预设 API 和 `lantern-presets.json` 继续独立使用，不删除原预设。

自动保存通常在停止调节后约半秒提交，另有轮询检查。后端断开或写入失败会显示“尚未存盘”，保留浏览器数据并重试；关闭页面前应确认“已写入文件”。后端未运行时浏览器清理数据仍可能导致未同步修改丢失。

## 龙墙分区光效

主地图左侧展开“龙墙 · 分区光效”，点击“定位龙墙”可查看近景。参考预设采用金色双龙、红墙与宝珠、暖色瓦檐和台基、少量蓝紫点缀；左龙、右龙、宝珠、墙面、瓦檐、台基和蓝紫点缀可分别调节启用、颜色、本体亮度、环境外溢强度及距离，另有总亮度与纹理保留控制。

“另存方案”新增独立方案，“应用参考预设”仅恢复当前参数，不删除已保存方案。这些设置使用独立存储项 `qinhuai.dragon-wall-light.v1`，由主地图存档 API 自动同步到文件；关闭页面前仍应确认顶部存档状态显示已写入文件。日景、线框和隐藏模型时停用龙墙附加灯效。

## 主地图逐建筑灯效

主地图左侧的建筑选择栏共用于本体光效和环境外溢。选择建筑后，在下方展开“建筑总控”或需要的檐口、屋面、墙柱、窗户、匾额、装饰模块调节。各模块默认收起，只显示该建筑已识别的发光部分；马头墙保留窗户和压边照明的原有设计。模块收起不会关闭光效，光效开关在模块内部。

亮度为原效果的倍率，1 倍沿用当前收藏；默认沿用原收藏光色，选色后仅替换所选模块的颜色。环境外溢仍在相邻的独立折叠模块中调节。全局曝光与光晕继续由原主地图模块管理。

使用独立存储项 `qinhuai.main-building-lights.v1`，按建筑 ID 保存当前参数及命名方案，不改写试灯页收藏。另存总是新增方案；恢复原灯效仅将本栋的附加调整恢复为默认，不删除任何方案。旧存档没有此项时维持原景，不在首次加载时写入默认值。新增项通过现有文件后端保存，仍以顶部“已写入文件”为确认依据。

## 文件位置

默认目录：`E:/soft/project/codex-Qinhuai/outputs/qinhuai-dual-era/.local-data/`

- `main-scene-settings.json`：当前主场景设置，带修订号。
- `main-scene-settings.json.bak`：上一个有效版本。
- `main-scene-history/`：最近 60 个历史修订。
- `chrome-setting-snapshots/`：首次读取、冲突或主动采用浏览器版本时保存的原样快照，按内容去重，不自动轮换删除。
- `lantern-presets.json`：原有试灯室存档，不被主场景文件替代。

字符串按原格式保存，包括未知字段、零值和自定义预设。写盘使用临时文件、刷新、原子替换和跨进程锁；同一参数的陈旧写入被拒绝。损坏主文件会尝试恢复上一个有效版本并保留损坏文件；所有版本都无效时停止保存，不写默认值。

这些机制降低误覆盖和写入中断风险，但不能保证磁盘损坏、手动删除或系统故障时绝不丢失。请定期把整个 `.local-data` 目录复制到其他磁盘；“导出备份”可额外下载当前浏览器快照。删除文件或恢复历史前先停止相关服务并另作副本，不要在运行中直接覆盖数据库文件。

## 启动

在 `E:/soft/project/codex-Qinhuai/outputs/qinhuai-dual-era` 执行：

```powershell
$env:PORT = '4180'
& 'E:/node/node.exe' game/serve.cjs
```

`workshop/serve.cjs` 也已接入相同存档 API。不要在同一端口重复启动服务。

可选兼容服务：旧的纯静态服务仍运行时，可单独执行 `E:/node/node.exe game/scene-storage-server.cjs`，监听 4186。前端仅在同源 API 返回 404 时回退到此服务。它与集成服务共享同一目录和文件锁，不必同时运行。只允许指定的本机页面来源，不对外网提供服务。可通过 `LANTERN_DATA_DIR` 指定存储目录。

### 石桥灯光（2026-10-19）

主场景建筑选择栏中的“秦淮河 · 石桥”使用稳定 ID `bridge-riverfront`，仍保存在 `qinhuai.main-building-lights.v1` 的 buildings / presets 中。栏杆、桥身与桥墩、桥洞与石雕、桥面分别有开关、亮度倍率和颜色，沿用逐建筑模块的另存功能。外溢仍存于原外溢记录，水面倒影跟随各部分光色及开关。

未设置过石桥时，自动显示内置“金栏暖石”参考图效果；初始化不会写入或覆盖用户存档。“应用参考图”只恢复当前石桥的已知灯光参数，保留未知字段、其他建筑和全部另存方案。原 GLB、白天材质及其他建筑预设不变。夜景取景栏新增“石桥 · 金栏暖石近景”。

### 天下文枢门下地面照明（2026-10-19）

在主地图建筑选择栏选择天下文枢牌坊后，展开“牌坊正下方 · 地面暖光”。内置“门下暖金”参考预设照亮牌坊中间通道，向周围柔和衰减并保留地砖纹理。可调启用、颜色、亮度、横向宽度、前后范围、左右及前后位置偏移、旋转角度和边缘柔和度，受建筑总开关及总亮度控制，白天停用。

参数保存在 `qinhuai.main-building-lights.v1` 的 `buildings.gate.groundProjection`，随当前建筑自动存储，并纳入建筑另存方案。旧记录缺少该字段时仅在画面中采用内置预设，初始化不写入默认值。应用参考预设保留未知字段、其他建筑及全部旧方案；实际写盘仍以“已写入文件”为准。

### 街区 0780 与夫子庙周边 0751：分层窗光（2026-10-19）

主地图左侧选择“街区建筑 · 0780号”或“夫子庙周边 · 0751号”，在建筑选择栏下方分别展开“一层窗户 · 本体与透光外溢”和“二层窗户 · 本体与透光外溢”。每层支持独立启用、窗户亮度倍率和光色；模块内的“本层窗户 · 透光外溢”可独立设置启用、颜色、强度、照射距离、衰减距离、展开角度及边缘柔和度。外溢可以跟随本层窗色，也可以单独选色。原“窗户共同基准 · 原有设置”继续保留，建筑总控及共同基准的开关、亮度倍率仍然生效。

通过 tile-10 中实际窗户的世界高度识别楼层；0753 的楼层高度单独校准，避免将低一些的二层窗口切入一层。窗格纹理、模型和日景材质继续沿用。两层分别从实际窗面生成地面透光外溢，高层按高度衰减；建筑原有屋檐及环境外溢继续保留。

数据使用原有 `qinhuai.main-building-lights.v1`，位于 `buildings[建筑ID].windowFloors.first / second`，外溢参数位于各层的 `spill`。调节后自动同步文件，另存建筑方案也包含两层参数。旧数据缺少此字段时继续使用旧灯效，仅在界面中显示继承值，不主动迁移、写入默认值或删除旧收藏。首次调节时保存两层的参数，并将这两栋的窗户外溢分层计算；原有建筑环境外溢模块仍负责其余本体部分。
